# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing site for **Rocamar**, three independent rental villas (Garza, Pelícano, Iguana) in Playa Blanca, Costa Rica. Bookings are handled by an external operator — every CTA links out to `https://rentaspuravida.com`; there is no booking engine, backend, or form.

Astro 5 project, but **almost nothing here is an Astro component**. The landing is a hand-off artifact: monolithic HTML files in `public/` that Astro copies verbatim into `dist/` (see commit `835b3fe`, "servir landing como static asset"). `npm run build` does little more than copy and minify.

## Do not hand-edit `public/` — it is generated

`public/` is an **output**, not a source. It is regenerated by a sync script that pulls from an Open Design project running on devbox:

```
Open Design project (devbox, :7456)
  → ~/rocamar/sync.sh  (wraps ~/tools/od-sync.sh)
    → web/public/
      → sync.sh --push  (commit + push to git@github-rocamar:grojass/rocamar.git, main)
        → prod (rocamar-prod / CT 127): ~/deploy.sh
          → sudo /usr/local/sbin/rocamar-deploy  (rsync -av --delete dist/ → /var/www/rocamar/)
```

OD project ids (`.sync-projects.conf` on devbox): `f4760ea0-…` → `main`, `ad8d1545-…` → `v2`, `277de0ec-…` → `garza`, `34055b2e-…` → `pelicano`, `00bdf4d6-…` → `iguana`. A slug is also the URL: `main` is `/`, everything else is `/<slug>/`.

### Where Open Design actually runs

OD runs as the docker container `open-design`, published on `127.0.0.1:7456`, with Caddy in front of it at `https://10.0.1.160` (self-signed cert from `~/tools/certs/`). `~/rocamar/{start,stop}.sh` → `~/tools/od-{start,stop}.sh` drive that container and check the port afterwards instead of assuming.

Its store is a bind mount of `~/tools/open-design/.od` — the same directory `od-sync.sh` reads — and the container runs as uid 1000 so it can write there. **That coupling is the point: what you edit in the browser is what ships.**

It has not always been true. Until 2026-09-21 the container mounted a named volume instead, so the UI and the sync worked on different files: the container's `projects/` was empty, its database knew nothing about `main` or `v2`, and design changes made in the browser could never reach the site. Nothing signalled the split — the UI worked, the sync worked, each on its own files. If the UI ever stops showing the projects listed above, check the mount first:

```bash
docker inspect open-design --format '{{range .Mounts}}{{.Type}} {{.Source}} → {{.Destination}}{{end}}'
# want: bind /home/grojas/tools/open-design/.od → /app/.od
```

The compose file is `~/tools/open-design/deploy/docker-compose.yml`. The container that ran until then had been created from `~/rocamar/design/deploy/docker-compose.yml`, a path that no longer exists — so treat a running container as no evidence that its definition is still on disk. The old volume `open-design_open_design_data` is still declared but unmounted, so its data survives.

A project's design system is fixed when the project is created; there is no setting for it afterwards, and the picker resets to the default on every page load. Pick it before typing the name.

The daemon rejects any `/api` call whose `Origin` it does not know, with a 403 and no explanation in the UI beyond `Daemon responded with 403`. Because the UI is reached through Caddy at `https://10.0.1.160` rather than on `:7456`, that origin has to be listed in `OPEN_DESIGN_ALLOWED_ORIGINS` (`deploy/.env`). It is a container setting, so exporting `OD_ALLOWED_ORIGINS` on the host does nothing.

OD drives a code-agent CLI that it finds by scanning `PATH` **inside the container**, and the image ships none on purpose. Claude Code is mounted in rather than installed: the host's own copy is glibc-linked and the image is Alpine, so `~/tools/claude-musl/` holds the `linux-x64-musl` build, mounted read-only at `/opt/claude` and prepended to `PATH` in the compose file. It authenticates separately from the host — its HOME is `~/tools/claude-home`, not `~/.claude` — so a fresh container needs `/login` once:

```bash
docker exec -it open-design claude   # then /login
```

Two consequences worth internalizing:

- A patch applied by hand in `public/` survives until the next `./sync.sh` and then vanishes silently — HTML is copied whole-file, so there is no conflict and no warning. The durable place for a content or markup change is the **Open Design project**, which lives only on devbox at `~/tools/open-design/.od/projects/<uuid>/`.
- `/var/www/rocamar` on prod is further downstream still, and the rsync runs with `--delete`: any file created there that is not in `dist/` is removed on the next deploy. It is also web-served, so anything left there is public.

The clone at `/home/rocamar/app` on prod is a deploy-side checkout, not a place to develop. The development clone is `/home/grojas/rocamar/web` on devbox (10.0.1.160); the surrounding `~/rocamar/{sync.sh,start.sh,stop.sh,.od-site.conf,.sync-projects.conf}` is dev tooling outside the repo.

### What sync does to the files

`od-sync.sh` copies the **transitive closure** of `index.html`: every file in the OD project whose name appears in an HTML already included, recursively. Files the entry page never reaches stay behind (an OD project dir accumulates drafts, screenshots and rejected shots — currently ~124 MB of which ~78 MB is reachable).

- **HTML** is copied byte for byte, then has its image references repointed to `/assets/…`.
- **Images** are resized to 2000px on the long edge and re-encoded (mozjpeg q80) by `od-optimize.mjs`, into `public/assets/` (`public/assets/<slug>/` for variants). Filenames and formats are preserved, EXIF — including GPS — is dropped, and the originals in the OD project are never modified. The current set is 44 images, 78.5 MB → 14.4 MB.
- Staleness is by **mtime**, not content: neither an optimized image nor a rewritten HTML ever equals its source byte for byte.
- Nothing is ever deleted from `public/`. A renamed or dropped photo leaves its old file behind; prune by hand.

Tuning knobs, overridable per site in `.od-site.conf`: `IMG_MAX_WIDTH` (2000), `IMG_QUALITY` (80).

**Images belong under `/assets/`**, which is the one path nginx caches as immutable for a year — that is why the rewrite exists.

## Commands

```
npm run dev       # astro dev — local preview on devbox
npm run build     # astro build → dist/
~/rocamar/sync.sh # pull the OD projects into public/  (--push to also commit and push)
~/deploy.sh       # ON PROD, as user rocamar: pull, build, rsync to /var/www/rocamar
```

No tests, no linter. Verification is visual: build and look at the page at phone width.

## Hosting

Published at **https://rocamar.retailyx.com** — Cloudflare DNS in front of aws-traefik, which routes to nginx on CT 127 (`/etc/nginx/sites-available/rocamar`, `root /var/www/rocamar`). nginx is plain HTTP on the internal network and still declares `server_name _;` with `default_server`, so it answers on any Host. `astro.config.mjs` sets `site: "https://rocamar.retailyx.com"`.

nginx serves `try_files $uri $uri/ =404;` — a missing file 404s properly. `location /assets/` carries immutable 1-year caching, while `index.html` is sent `no-store`; that caching is why sync moves photos to `/assets/`.

It was not always this way. The vhost was copy-pasted from the SPA boxes in the fleet and carried `try_files $uri $uri/ /index.html`, which made **every** missing path return 200 with the home page — `/v2/garza.html`, `/noexiste-xyz` and image URLs all rendered the landing. Missing files were invisible for as long as that lasted. It was changed to `=404` on 2026-09-21 (backup: `/etc/nginx/sites-available/rocamar.bak-20260921-181529`). If a page ever starts answering 200 with home-page HTML again, suspect a reverted vhost.

This nginx config lives only on CT 127 and is **not** managed by Ansible: the fleet playbook on bastion (`~/infra-ansible/`) does hardening and promtail only, no roles or templates for nginx. `server_name _;` with `default_server` is part of the same inherited boilerplate and is shared with the other boxes — leave it alone without a concrete reason. Source of truth for this site: the content in this repo on devbox, the nginx config on CT 127 itself.

Cloudflare has **Email Obfuscation** on: the published page is ~137 bytes larger than the file on disk because `mailto:` links are rewritten to `/cdn-cgi/l/email-protection#…` with an injected `email-decode.min.js`. Email CTAs therefore depend on JavaScript in production but not locally — worth remembering when diffing deployed HTML against `dist/`.

## The two designs are independent

`main` (`public/index.html`) and `v2` (`public/v2/index.html`) are separate designs of the same content, from separate OD projects, sharing no markup, no tokens and no section ids. **A change to shared content is two changes, in two projects.** Do not port one file's tokens into the other.

| | `index.html` (main) | `v2/index.html` |
|---|---|---|
| Sections | `#about #villas #gallery #location #faq #contact` (+`#nav`) | `#modules #gallery #location #testimonials #faq #contact` |
| Tokens | `--accent --gold --cream --ink --font-display --space-*` | unrelated hex palette |
| Fonts | Cormorant Garamond (Google Fonts) | system fonts |
| JS | nav `.scrolled` on scroll, `.faq-question` accordion, IntersectionObserver adding `.visible` to `.reveal` | `.faq-question` accordion |
| Photos | real, in `/assets/` | none yet |
| Testimonials | none | present (samples) |

Both link out to three villa detail pages of their own: `villa-garza.html` / `villa-iguana.html` / `villa-pelicano.html` at the root for main, `v2/garza.html` / `v2/golondrina.html` / `v2/iguana.html` for v2. These reached the repo only once sync started following references — they had never been deployed.

New sections in `index.html` need `.reveal` to animate in.

## Bilingual copy — only `v2` actually works

`v2/index.html` carries both languages as duplicated sibling elements toggled purely by CSS, with a `rocamar-lang` localStorage key:

```css
[data-lang="en"] [data-es], [data-lang="es"] [data-en] { display: none; }
```

**`index.html` is Spanish only.** The page before the redesign did translate — paired `data-es`/`data-en` attributes swapped by inline JS, `rocamar.lang` localStorage key — but that mechanism did not survive it. The redesign kept an ES/EN toggle in the nav with no click handler behind it and no English copy anywhere in the file; the dead buttons were removed on 2026-09-21 rather than shipped. Bringing English back means adding both the copy and a swapper **in the OD project**, not patching `public/`.

Spanish copy is Costa Rican **voseo** ("reservá", "dormís", "consultá"). Keep that register.

## Villa facts (repeated in hero stats, cards and FAQ — and in the OD project)

As stated by the current `index.html`:

| Villa | Floor | Bedrooms / baths | Sleeps |
|---|---|---|---|
| Garza | Upper, sea view | 2 / 1 | 5 |
| Pelícano | Upper, sea view | 2 / 1 | 6 |
| Iguana | Ground, private garden + rancho | 3 / 3 | 8 |

Group total is 14. Garza and Pelícano have street-level entrances with an internal staircase; Iguana is a level below the parking and reached by stairs. The only shared space is 6 covered parking spots; garden and rancho are exclusive to Iguana. Sea view 50 m away, 10 minutes' walk to the beach; Blue Flag beach, white sand, no jet skis.

`v2` still states the older figures (2/2 baths, Iguana 6–8) and so does the currently deployed page. **The two designs disagree**; treat `index.html` as the newer claim and fix v2 in its OD project rather than in `public/`.

Change one of these numbers and you change it in three places per page, per design — and in the OD project, or the next sync reverts it.
